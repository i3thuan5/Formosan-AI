# 延遲測試作業慣例

這份文件記錄**寫 `RESULTS.md`** 的規則。怎麼跑測試看 [README.md](README.md)，
測試規格看 [METHOD.md](METHOD.md)。

## 一、每次評測都要寫兩件事

每跑一次新的評測，新增到 `RESULTS.md` 的那個章節必須同時包含：

1. **這次評測本身的結果**（推論延遲表、上傳/總延遲、分項、排名、觀察）。
2. **和上一次評測的比較**（差異、加速或變慢倍數、排名有沒有變、原因分析）。

這兩塊寫在**同一個章節**裡（結果在前、比較在後的小節），不要分開成兩個獨立的頂層章節。
比較的對象永遠是**上一次**（時間上緊接在前的那次），不是最早的基準線。

## 二、`RESULTS.md` 的排列順序：新的在上面

`RESULTS.md` 整份文件由新到舊排列，結構固定如下：

1. **目錄**：列出歷次評測的時間＋標題，每次一行（例如 `2026-08-28 03:xx｜第 3 次：MT 加 GPU 設定`）。
2. **最新一次報告**（結果＋和上一次的比較）。
3. **上一次報告**（結果＋和上上一次的比較）。
4. ……依序往下，愈舊排愈後面，最早的基準線（第 1 次）在文件最後面，沒有「和上一次比較」的小節（因為它是第一次）。

也就是說，**新增一次評測時，是把新章節插進目錄下方、第一個報告章節的位置**，
不是加到檔案尾端。舊章節本身的內容不用重寫，只需要調整順序、以及目錄要跟著更新。
