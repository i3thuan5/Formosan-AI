`tts` 是最慢的，比最快的 `asr` 慢 **5.8 倍**。

### 觀察

1. **`asr`（Whisper）比 `asr-kaldi`（Vosk）快 2.4 倍。** 這與直覺不符——Kaldi/Vosk 是 CPU 的
   輕量模型，Whisper-large-v2 是大模型。合理的解釋是線上的 Whisper 有 GPU（ct2 float16）
   可用，Vosk 則是在 CPU 上跑，再加上它是一塊一塊（4000 bytes）掃描音檔。
2. **`tts` 是效能瓶頸。** F5-TTS 是 diffusion 架構，`nfe_step=32` 要跑 32 步，
   還要過 vocoder，所以 10 秒以內的短句就要 5～9 秒。使用者感受最明顯的等待就在這裡。
3. **尾端（tail）很穩定。** 四個模型的 p99 都沒有偏離太多，只有 `asr`（max 4.09s）與
   `asr-kaldi`（max 6.06s）各有 1 筆特別高的，看起來是偶發的（cold start 或當下有
   其他人在使用），不是系統性的問題。
4. **100 次全部沒有失敗**（`http_req_failed` 0%、`checks` 100%），
   每次的辨識／翻譯／合成結果都通過內容檢查。

### 注意事項

- 這是**線上正式站**的測量，會受當下網路狀況與同時使用人數影響。
  要比較時，必須用相同的測試資料與相同的方法（`ITERATIONS=100`、`vus=1`、依序執行），
  最好也挑差不多的時段。
- 這**不是**壓力測試（只有 1 個 VU）。若要知道並發時的表現，需另外寫 `constant-arrival-rate` 的情境。
